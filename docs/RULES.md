# Lint rules

Generated by `sekkei rules`. Severities: error blocks `brief`/`plan` (unless `--force`); `--strict` promotes warnings.

| id | severity | rule | hint |
|---|---|---|---|
| S001 | error | duplicate id | Ids must be unique across the whole design; rename one of them. |
| S002 | error | invalid id | Use letters, digits, '-', '_' or '.', starting with a letter, e.g. WP-3. |
| S003 | warning | id prefix convention | Use the conventional prefix so agents and humans can tell what an id refers to. |
| S004 | error | dangling reference | Every reference must name an existing id of the right kind; add the element or fix the id. |
| S005 | error | invalid enumeration value | Use one of the listed values (see `sekkei schema`). |
| S006 | warning | unknown key | Probably a typo; run `sekkei schema` for the accepted keys. |
| S007 | error | missing required text | Fill in the field; an element without it cannot be briefed. |
| S008 | error | empty design | A design needs at least one requirement, one component and one work package. |
| C001 | error | component requires its own interface | A component does not call itself through an interface; drop it from `requires`. |
| C002 | error | component dependency cycle | Break the cycle: extract a shared interface, or turn one edge into an event. |
| C003 | error | flow step via an interface the target does not own | `via` must be an interface owned by `to`. |
| C004 | error | flow step uses an undeclared dependency | Add the interface to the calling component's `requires`. |
| C005 | error | work-package dependency cycle | Packages must form a DAG; split or reorder them. |
| C006 | error | package implements an interface whose owner it does not build | Add the owning component to the package's `components`, or move the interface. |
| C007 | warning | implicit package dependency | Add the target package to `depends_on` (or stub the interface and say so in notes). |
| C008 | error | decision choice is not one of its options | Set `choice` to the name of one of the listed options. |
| C009 | error | package depends on itself | Remove the self-reference from `depends_on`. |
| V001 | error | requirement satisfied by no component | Name the component(s) that satisfy it in their `satisfies`, or drop the requirement. |
| V002 | error | requirement delivered by no work package | Add it to the `satisfies` of the package that delivers it. |
| V003 | error | component built by no work package | Every component must appear in the `components` of at least one package. |
| V004 | error | interface implemented by no work package | Add it to the `implements` of the package that builds its owner. |
| V005 | error | work package without acceptance checks | Add at least one check; a package with no way to pass cannot be accepted. |
| V006 | error | non-functional requirement without a measurable metric | Give it a metric with a name and a target (e.g. p95 latency, <= 200 ms). |
| V007 | warning | risk without mitigation | State what is done about it, or accept it explicitly in the mitigation text. |
| V008 | info | orphan interface | Nobody requires it and no flow uses it; remove it or declare its consumer. |
| V009 | warning | component satisfies no requirement | If it is needed, some requirement needs it; add it to `satisfies` or remove the component. |
| V010 | warning | test/command acceptance check without a command | Give the exact shell command that must exit 0. |
| V011 | warning | decision with fewer than two options | A decision with one option is a statement; record what else was considered. |
| A001 | error | work package without a write scope | List the files/directories the agent may change in `files`. |
| A002 | error | unordered packages share a write scope | Order them with `depends_on`, or split the shared file between them. |
| A003 | warning | work package too large for one agent session | Split it: at most 4 components / 6 interfaces per package keeps a brief within one context. |
| A004 | error | metric acceptance check not tied to a non-functional requirement | Set `metric` to the id of a nonfunctional requirement with a target. |
| A005 | warning | no test command in conventions | Set conventions.test_command so every brief tells the agent how to run the tests. |
| Q001 | warning | vague wording without a metric | Replace the adjective with a number, or add a metric to the requirement. |
| Q002 | warning | requirement statement too short | A requirement should say who needs what and under which condition. |
| Q003 | warning | work-package goal too short | State the outcome the agent must produce, not just a title. |
